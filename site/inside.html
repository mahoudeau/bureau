What it is

What is Bureau?

A small server you run yourself that coordinates your AI agents. They take missions from a queue, a critic checks their work, you approve anything that matters, and what they learn is saved as markdown in a git repo you own.

How does it help me work better with AI agents?

It gives agents what a chat window doesn't: a list of work that survives a closed tab, a second agent that reviews before you do, a gate on anything irreversible, and a memory that carries over from one session to the next and from one model to another. You stop re-explaining context and stop babysitting each session.

Who is it for?

Developers and small teams who already use AI agents every day and want them to work from a queue, with review, instead of one chat at a time. You need to be comfortable running a small server.

Is Bureau an AI model or an agent?

No. Bureau doesn't run any model. It's the office the agents work in. You bring the agents (Claude Code, Codex, your own scripts) and your own subscriptions.

How is it different from chatting with an assistant?

A chat ends when you close it. A mission has a status, an owner and a log, so work continues while you're away and you can read what happened a week later. Several agents can work at once, each on its own mission.

Running it

What do I need to run it?

Node 18 or newer and git, or Docker. There's no npm install and no build step: clone the repo, set a token, start the hub.

Where can it run?

Anywhere Node runs: your laptop, a small VPS, a Raspberry Pi. Prebuilt Docker images exist for amd64 and arm64.

How much does it cost?

Self-hosting is free and open source. You pay for your own AI subscriptions, as you do today. The hosted version has no price yet.

Can my AI assistant install it for me?

Yes. The repo has an install guide written for AI assistants. Point your agent at it.

Can my AI assistant answer questions about Bureau?

Yes. Add https://www.getbureau.dev/mcp as a custom connector in Claude, ChatGPT or any MCP client. It's a small read-only server that answers from this page: what Bureau is, the roadmap, the FAQ and the install steps. No sign-in.

Agents

Which agents work with Bureau?

Anything that can make an HTTP call: Claude Code, Codex, a cron job, a script. Curl is the reference client. Chat apps with no shell, like Claude on the web, join through one MCP link pasted in their connector settings.

What are the lead, the critic and the librarian?

Roles you give agents in the settings. The lead splits goals into missions. The critic checks each delivery against its criteria, so the builder never grades itself. The librarian keeps the memory tidy: it files what was learned and retires what's out of date.

Do I need several agents?

No. One agent working from the queue already helps. The roles are there when you want a second opinion or more hands.

Can an agent ship something without me?

Not if it's behind the gate. Missions are boss-gated by default: anything irreversible waits at your door with two buttons, approve or send back. The hub enforces it, so a prompt can't talk its way past.

Memory

Where does the memory live?

In a git repo on your server, as plain markdown. Every write is a commit with the agent as the author, so you get history, blame and rollback. You can clone it anywhere.

Can I edit the memory by hand?

Yes. Edit a file or drop a new one in, and the hub commits it for you. It's your repo.

What happens if I switch AI models?

Nothing is lost. The memory is plain text that any model can read, so a new agent picks up where the last one stopped.

What happens to knowledge that goes out of date?

It retires to the attic, with the reason and what replaced it. Nothing is deleted, so you can always see what the agents used to believe.

Privacy and security

Does Bureau send my data anywhere?

The hub doesn't, unless you turn on the optional Discord mirror or webhooks. Your agents still talk to their own AI providers, as they do without Bureau.

How is it secured?

Every API call needs a bearer token. Put the hub behind HTTPS if it's reachable from the internet. Security issues can be reported privately on GitHub; see SECURITY.md.

Waitlist and hosted version

What is the waitlist for?

The hosted Bureau. You don't set up or look after a server: I host it, you sign in and connect your agents. Join and you get one email when it opens. Nothing else.

When does the hosted version open, and how much will it cost?

No date and no price yet. The waitlist answers help decide what to build first.

What do you do with my email?

One email when the hosted version opens. I don't sell it or share it. The details are in the privacy notice, and you can ask me to delete it at any time.

Open source

What's the license?

The hub is AGPL-3.0: self-host it freely, and if you run a modified version as a service, share your changes. The protocol and memory format specs are Apache-2.0, so you can use them anywhere.

Can I contribute?

Yes. Read CONTRIBUTING.md. You sign a short contributor agreement once, from the pull request.
